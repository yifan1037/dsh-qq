# 安全模型

## 威胁假设

这是**个人陪伴**取向的项目，不是企业客服。信任模型是：

- 部署者 = 使用者 = 被回复的人（`ownerQQ`）
- 机器上可能有隐私文件（聊天记录、账号、工作资料）
- 插件**会**读这些文件（如果你给了权限）

## 权限分层

| 层级 | 名称 | 能力 | 默认 |
|---|---|---|---|
| L2 | 电脑操作 | 截图、鼠标、键盘（`computer` 工具） | 关 |
| L3 | 全盘只读 | 读任意位置文档（绕开目录白名单） | 关 |
| L4 | 探索模式 | 执行命令、写文件（`mcp__shell__*`） | 关 |
| L5 | 自主探索 | 无人时按时间点自己醒来逛允许目录 | 关 |
| — | 工作模式 | 挂工程工具（pwsh/fs/tasks） | 关 |
| — | 紧急停止 | 一键关闭上面全部 | — |

**默认全关**。每项都要显式打开，管理台「权限」页操作。

## 护栏

### 文件读取（mcp-files）

- 只允许：桌面 / 文档 / 下载 / 工作区（除非开 L3）
- 拒绝凭据类：`.credentials.yaml`、`id_rsa`、`*.pem`、`Cookies`、`Login Data`、`config.json` 等
- 不解析加密/扫描 PDF 之外的二进制

### 命令执行（mcp-shell）

- 需要 `explore` 或工作模式
- 受 `panic` 标志控制
- 每次执行写 `~/.dsh/qq-native/state/explore.log`

### 屏幕（screenwatch / eyes）

- **零输入注入**：只截图，没有鼠标键盘代码
- 眼睛会话的 prompt 硬约束"只能截图，不能点击/移动/打字"
- 看到敏感信息只说"画面里有敏感信息，我不细看"
- 默认关；后台轮询配置，20 秒内可生效

### 桌面操作（computer-use）

- 由第三方 `dsh-computer-use-mode` 提供，自带守卫：
  - STOP 文件
  - 应用白名单
  - 敏感窗口黑名单（UAC、密码管理器、银行）
  - 动作预算
- 本插件默认不引入它（聊天预设不含 `computer` 工具）

## 数据出站

| 数据 | 去哪 |
|---|---|
| QQ 消息内容 | 你的 DSH 模型服务（按你的 DSH 配置） |
| 截图 | 存本地；仅在"眼睛"会话里作为图片输入给模型 |
| 记忆 / 人设 / 会话 | 只在本地 `~/.dsh/` |
| 成本记录 | 只有 token 数，无内容 |

**没有任何数据发往项目作者。**

## 凭据存放

| 凭据 | 位置 |
|---|---|
| SnowLuma HTTP/WS token | SnowLuma 自己的配置目录（本插件只读） |
| 管理台 token | `~/.dsh/qq-personal/settings.json` 的 `consoleToken` |
| DSH 鉴权 | DSH 自己管理（本插件不接触） |

不要在 `config.json` 里手写 token —— 让它从 `snowlumaDir` 读。

## 已知风险

1. **腾讯 ToS**：个人 QQ 自动化可能违反服务条款。自担风险。
2. **SnowLuma EULA**：禁止打包分发；本仓库不包含它。
3. **模型幻觉导致误操作**：开了 L4/电脑操作后，她可能执行你没预期的操作。建议：
   - 平时全关，用时再开
   - 敏感操作前在管理台确认
   - 随时紧急停止
4. **会话串用**：同一个 DSH 会话不能被两个进程同时投消息（会抢答）。双跑期用 `triggerPrefix` 隔离。
5. **截图隐私**：开屏幕监控 = 她能看你整个桌面。用完记得关。

## 安全建议

- `ownerQQ` 只填自己的号，不要用机器人号收陌生人消息
- 管理台不要暴露到公网（默认只绑 127.0.0.1）
- 定期备份 `~/.dsh/qq-native` + `~/.dsh/qq-memory`，泄露时知道丢了什么
- 不要在多台机器上同时跑同一个 QQ 账号

## 报告问题

发现安全问题：不要在公开 issue 里贴 token / 聊天记录 / 截图。
先私信维护者（或先写一个不含敏感数据的复现步骤）。
