# 可借鉴清单：SurfCore（先记，后做）

> 来源：[Mieksido/surfcore](https://github.com/Mieksido/surfcore)（0.6.20，MIT，DSH 身份系统：QQ × B站 × 桌宠）
> 记录时间：2026-10-28
> 结论：**抄它的「怎么想」，不抄它的「做多少」。**

## 它的定位 vs 我们的

| | SurfCore | dsh-qq |
|---|---|---|
| 定位 | 给 agent 一个身份（人格化操作系统） | 给 DSH 开一扇 QQ 的窗（通道） |
| 架构 | 双进程（插件 + bridge 进程） | 插件内直连，零额外进程 |
| 范围 | QQ + B站 + 桌宠 + 语音 | 只做 QQ，但求「用户能做的都能做」 |

我们的差异化：零进程、复用旧会话、小到能读懂（~2,400 行）。

---

## 一、值得借鉴的 7 个优点

### 1. 目的机制（Purpose）— 最值得抄

```
近期记忆 → 提炼「目的」→ 生成话 → 发送 → 解析回执 → 状态迁移
   （想弄明白 / 想做 / 想分享 / 想索取）
```

关键设计：

| 设计 | 价值 |
|---|---|
| 素材来自记忆 | 说的是最近在想的事，不是模板 |
| 目标假设 | 提出假设，下次聊天验证 |
| 预览（零副作用） | 先看会说什么，再决定发不发 |
| 安静时段 / 专注模式 | 不打扰是自由的一部分 |
| 回执确认 | 发了才算数（turn/end + 发送记录） |
| 载体互斥 | 同一时刻只有一个执行者，不会双发 |
| 单一写入者状态文件 | 并发安全 |

### 2. 发言决策（像群友，不像复读机）

自己判断：要不要看、要不要说、说几条、引用谁、说完了怎么潜水（带"下次怎么接"的线索）。

我们现状：档位（@/关键词/概率）+ 冷却。升级方向：**模型决策 + 硬闸门兜底**。

### 3. 记忆会衰减、会遗忘

| SurfCore | 我们 |
|---|---|
| 衰减卡（进 prompt）+ 全量卡（只存档） | 只增不减的索引 |
| 80/90/100% 容量告警 | 无告警 |
| 每 10 分钟摄取 | 写入即整理 |

**会忘才像人**；也防记忆库无限膨胀。

### 4. 作息与额度

生物钟、每日额度、安静时段、专注模式。
我们已有"主动每天 ≤3、白天"，缺"她自己的作息"。

### 5. 工具门控发言（二代）

发言必须调工具（`qq_send_private_message`），而不是文本自动转发。
好处：她"决定说"才说；可控、可审计；模型输出不会失控自动发出。
我们已有动作层（`lib/actions.mjs`），可以对接。

### 6. 配置热生效 / 状态工程

- 载体切换 30 秒内生效，不用重启
- 单一写入者、互斥、回落（永不双发）

我们现状：只有屏幕监控开关会轮询热生效，其余配置要重启 DSH。

### 7. 可解释性

设置页 14 个标签页，含「诊断」「对齐」，能回答"她为什么这么说"。
我们的审计日志只有原始记录，缺"为什么"。

## 二、落地映射（估计 ~830 行）

| 借鉴 | 模块 | 行数 |
|---|---|---|
| 目的机制 | `lib/purpose.mjs` | ~250 |
| 发言决策 | `lib/participation.mjs` | ~180 |
| 记忆衰减 | `lib/memory-decay.mjs` | ~120 |
| 作息额度 | `lib/presence.mjs` | ~100 |
| 工具门控发送 | 扩 `actions.mjs` + send 工具 | ~120 |
| 配置热生效 | 推广屏幕监控的轮询 | ~60 |

## 三、不建议抄

| 不抄 | 原因 |
|---|---|
| B站身份 | 另一个平台，与「QQ 通道」定位无关 |
| 桌宠 / 语音 | 配套仓库，与通道定位无关 |
| 双进程架构 | 我们的卖点就是零额外进程 |
| 沙箱 ACL | Windows 深耦合，权限分层已够 |

## 四、落地顺序（性价比）

| 顺序 | 模块 | 理由 |
|---|---|---|
| 1 | `participation.mjs` 发言决策 | 群聊刚做好，正缺"该不该说"；改动小、效果立现 |
| 2 | `purpose.mjs` 目的机制 | 让"主动"从计时器升级成"她真有事想说" |
| 3 | `memory-decay.mjs` 衰减 | 会忘才像人，防膨胀 |
| 4 | `presence.mjs` 作息 | 让"她的时间"有形状 |
| 5 | 工具门控发送 | 工程更稳，但会改现有发送链路，放后面 |

## 五、验收标准

| 能力 | 现在 | 做完 |
|---|---|---|
| 群里 | 按档位触发 | 判断该不该接，不该接就潜水 |
| 主动 | 4 小时空闲 → 说话 | 从记忆挑一个"想问的事" → 预览 → 发 |
| 记忆 | 只增不减 | 长期不提的降权淡出，容量告警 |
| 可解释 | 审计日志 | 每次主动/发言都有"为什么" |
